# GYSY_Simulation 仓储AGV调度仿真系统分析笔记

## 一、项目概述

**GYSY_Simulation** 是一个基于 **ProfControl V8** 平台的仓储 AGV 调度仿真脚本，使用 C# 编写，运行在 .NET 6.0 环境下。项目模拟了自动化立体仓库中 AGV 小车完成**入库**和**出库**全流程调度，包括货物生成/消耗、AGV 电量管理、任务分配与状态机驱动、跨层调度等核心逻辑。

### 1.1 文件结构与职责

| 文件名 | 行数 | 核心职责 |
|--------|------|----------|
| `script.cs` | 591 | **主入口 + 任务调度状态机**：`Main()` 初始化，每秒轮询推进入库/出库任务 |
| `Method.cs` | 789 | **数据结构 + 任务创建 + 货物模拟**：`TaskInfo` 实体类、`RandomGenerateCargo()`、`TaskCreat()` |
| `Charge.cs` | 261 | **AGV 电量仿真与充电管理**：模拟电量消耗、自动前往充电、充电中状态判断 |
| `globalusing.cs` | 62 | **全局引用**：ProfControl API、System 命名空间等全局 using |
| `project.config` | 195 | **编译配置**：引用程序集路径、编译过滤规则 |
| `GYSY_Simulation.csproj` | 129 | **项目文件**：.NET 6.0 目标框架、程序集引用清单 |

### 1.2 架构概览

```
Main() 入口
  ├── 等待工程加载 → 读取站点/AGV配置
  ├── 注册生产口(17个) + 出库口(24个)
  ├── 出入库限制推挤()
  ├── 上线车辆数(30)      → 控制30台AGV上线
  ├── InitAgvBattery()     → 随机初始化电量50~100%
  ├── AsyncHandle()        → 启动充电仿真(1s定时器)
  ├── 注册AGV/站台自定义属性
  ├── RandomGenerateCargo() → 50%随机填货 + 货物生成/消耗定时器
  ├── TaskCreat()          → WMS模拟任务创建(1s定时器)
  ├── 任务调度主循环(1s定时器) → 状态机推进所有未完成任务
  └── while(true) 保持主线程
```

## 二、核心数据结构 (`Method.cs`)

### 2.1 TaskInfo 任务实体类

```csharp
public class TaskInfo
{
    public string ID { get; set; }              // GUID唯一标识
    public TaskTypeEnum TaskType { get; set; }   // 入库/出库
    public DateTime OccurTime { get; set; }      // 创建时间戳
    public IAgv WorkAgv { get; set; }            // 执行AGV
    public IStation FromSta { get; set; }        // 取货起点
    public int Floor { get; set; }               // 楼层
    public IStation ToSta { get; set; }          // 送货终点
    public string Status { get; set; }           // 状态机状态
}
```

**状态机流转路径（8个状态）：**

```
"" → "找到Agv" → "前往取货点" → "到达取货点" → "取货中"
    → "前往送货点" → "到达送货点" → "送货中" → "完成"
```

### 2.2 任务列表与出入口集合

```csharp
SmartArray<TaskInfo> TaskInfos        // 全部任务（支持条件删除）
List<IStation> produceStas            // 17个生产口（入库起点）
List<IStation> exportStas1            // 24个出库口（出库终点）
```

### 2.3 静态配置参数

| 参数 | 值 | 含义 |
|------|-----|------|
| `initCargosPercent` | 0.5 | 初始货位填充比例 50% |
| `入库货物生成时间` | 310秒 | 生产口每310秒生成一个货物 |
| `出库货物消耗时间` | 18秒 | 出库口每18秒消耗一个货物 |
| `出库任务生成时间` | 0 | 计数器累计到18触发一次出库 |

入库口分5组（其中4组×4层），组间偏移12秒，层间偏移6秒，模拟升降梯逐层上移。

## 四、货物仿真 (`Method.cs:131-291`)

### 4.1 RandomGenerateCargo() — 初始随机填货

**`Method.cs:131-291`**

流程：
1. 初始化生产口/出库口倒计时器（`Tag2`）
2. 筛选"自动生成"货区站点
3. 清空旧货物 → 注册3种货物 + 1种托盘
4. 排除出入口，只保留存储库位
5. 按50%比例随机填充托盘+货物
6. 设置各组生产口初始倒计时（阶梯偏移）
7. 启动1秒定时器：

**生产口逻辑**（`:240-262`）：
- 站台无AGV + 为空 → 倒计时
- 到达310秒 → 生成一个"托盘_0+货物_0"，重置计时器
- 有AGV或货物 → 重置计时器

**出库口逻辑**（`:267-284`）：
- 站台有货物 + 无AGV → 倒计时
- 到达18秒 → 消耗（清除）货物，重置计时器

## 五、任务创建 (`Method.cs:303-667`)

### 5.1 TaskCreat() — 模拟WMS任务下发

**`Method.cs:303-667`** — 每秒轮询一次

**并发限制**（`:317`）：任务总数 < 50 且 未完成任务数 < 50

#### 入库任务创建（`:341-499`）

- 筛选有货 + 无未完成任务 + 无AGV的生产口
- 随机选择一个生产口
- 在同楼层巷道中**从前往后**找第一个空库位
- 防死锁检查：后续站点有入库任务则跳过当前位置
- 去重检查后添加到 `TaskInfos`

#### 出库任务创建（`:505-658`）

- 筛选空闲出库口 + 计数器 >= 18 触发
- 随机选一个出库口
- 在同楼层巷道中**从后往前**找第一个有货库位
- 防冲突检查：同一巷道未完成出库任务则跳过
- 创建成功则重置计数器

## 六、任务调度状态机 (`script.cs:163-548`)

### 6.1 入库状态机

| 状态 | 行为 |
|------|------|
| `""` | 找可用AGV：正常空闲(电量>20%) > 充电中(电量≥60%)，优先同层，无则跨层调车 |
| `"找到Agv"` | `GoTo` 导航到生产口 |
| `"前往取货点"` | 检测是否到达，未到则重发导航 |
| `"到达取货点"` | 执行"取货"动作集，`MoveToOtherArea` 将货物从站台→AGV |
| `"取货中"` | 取货完成 → `GoTo` 导航到目标库位 |
| `"前往送货点"` | 检测是否到达 |
| `"到达送货点"` | 执行"复位"动作集，`MoveToOtherArea` 将货物从AGV→库位 |
| `"送货中"` | 清理标记、统计、释放AGV → `"完成"` |

### 6.2 出库状态机

与入库对称，区别在于：
- FromSta = 有货库位，ToSta = 出库口
- 送货中检测 `IsEmpty()` 确认卸货完成
- 使用"取货"动作集卸货（与入库不同）

### 6.3 AGV选择策略

1. 优先同楼层正常空闲 AGV（电量 > 20% 且不充电）
2. 其次同楼层充电中但电量 ≥ 60% 可中断充电的 AGV
3. 再次跨楼层调度（需升降梯有余量，且目标楼层无重复调度标记）
4. 跨层调度使用 `GoTo` 回调异步完成

### 6.4 跨层调度防重复

```csharp
HashSet<string> 跨层已调度  // 记录已派车的目标楼层
```

- 派车时加入集合
- 目标楼层已有空闲AGV到达时移出
- 确保同一楼层不会重复派车

### 6.5 并发安全

`Chare.cs:190-239` 使用 `Hashtable agvToStaHash` + `lock` 保证多线程下AGV到站台的唯一性：

- `AddHash` — 添加AGV→站台映射，已存在返回false
- `RemoveHash` — 移除映射
- `UpdateTargetSta` — 更新目标站台（防止重复派车到同一站台）

## 七、AGV电量与充电管理 (`Charge.cs`)

### 7.1 InitAgvBattery() — 初始化电量

**`Charge.cs:20-32`**

- 所有上线AGV随机初始化 50~100% 电量
- 调用 `BatteryFromRecv(true)` 开启电量模拟

### 7.2 SimulateCharge() — 电量仿真

**`Charge.cs:36-82`** — 每1秒调用一次

**电量消耗**（每5秒）：
- 电量 -= 0.0108 → 约9小时消耗70%

**充电**（每10秒，仅限充电点上的AGV）：
- 电量 += 0.069 → 约2小时充满100%

### 7.3 AgvToChargeStation() — 自动充电调度

**`Charge.cs:86-125`**

触发条件：`Battery < 40` + 空闲 + 无货 + 未在充电

策略：
- 优先同楼层充电站
- 同层满则跨层（需升降梯有余量）
- 使用 `API.GetShortest` 寻路 + `GoTo` 导航
- 到达后回调中标记 `"正在充电"`

### 7.4 充电站集合

8个充电站：7229, 7230, 5244, 5245, 8344, 8345, 9967, 9968

### 7.5 充电状态判断

| 方法 | 功能 |
|------|------|
| `IsCharging(agv)` | 判断AGV是否在充电站上充电。电量≥100 → "停止充电"；≥60 → "正在充电" |
| `IsWorkingByCharged(agv)` | 充电中AGV能否接任务。电量<30 → false；≥60 → "停止充电接任务"，返回true |

## 十、关键设计要点总结

1. **状态机驱动**（script.cs:163-548）：8状态流转，异常时自动回退重试（如位置偏移回退到导航状态）
2. **定时器并发**：多个 `API.SetInterval(1000)` 并行运行（充电仿真、货物生成、任务创建、调度轮询）
3. **跨层调度**：通过升降梯在楼层间调车，使用 `HashSet` 防重复，`GetBestElevator` 选最优电梯
4. **电量管理**：电量随运行递减，低电量自动前往充电，充电达到60%可中断接任务
5. **防死锁**：巷道内任务创建时检查前方/后方是否有冲突任务
6. **防推挤**：出入口特殊配置，避免多AGV争抢
7. **异步回调同步**：`Hashtable` + `lock` 保证并发环境下AGV到站台的唯一性
8. **出入库对称性**：入库从前往后找空位，出库从后往前找货物，最大化巷道利用率
