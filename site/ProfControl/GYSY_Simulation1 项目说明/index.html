    GYSY_Simulation1 项目说明

    GYSY_Simulation1 项目说明

    项目概述

    基于 ProfControl V8 平台的多楼层 AGV 仓库仿真系统。4 层楼、6 部升降梯、50 台 AGV（30 台在线、20 台离线），模拟完整的入库/出库/充电流程。

    • 项目路径：E:\procon\loadingFiles\Remote\script\GYSY_Simulation1\
    • 框架：ProfControl V8（.NET 6.0），实现 IAppScript 接口
    • 语言：C#

    文件结构

    文件 说明
    script.cs 主入口 + 任务调度状态机 + 升降梯负载均衡
    Method.cs 数据结构、配置参数、货物初始化、任务创建、AGV 上线管理
    Charge.cs AGV 电量仿真 + 充电调度 + Hashtable 并发控制
    globalusing.cs 全局 using 引用
    GYSY_Simulation1.csproj 项目文件

    一、核心架构

    1.1 部分类拆分

    GYSY_Simulation 为 partial class，横跨 3 个文件： - script.cs：主流程（Main、状态机、跨层调度） - Method.cs：数据模型、配置、货物与任务 - Charge.cs：电池与充电逻辑

    1.2 任务状态机（8 状态）

    "" → "找到Agv" → "前往取货点" → "到达取货点" → "取货中"
  → "前往送货点" → "到达送货点" → "送货中" → "完成"

    可在 script.cs 第 164 行起查看完整状态机实现。

    1.3 任务类型

    类型 起点 终点 说明
    入库 生产口（17个） 存储库位 模拟货物入库上架
    出库 存储库位 出库口（24个） 模拟货物出库下架

    二、站点配置

    2.1 生产口（入库起点）：17 个

    4 个物理位置 × 4 层 + 1 个单层独立口，按组错开初始生成时间：

    组号 站点 ID 楼层
    0 4650 单层独立
    1 4647, 5509, 8609, 10232 1-4F
    2 4645, 5558, 8658, 10281 1-4F
    3 4437, 7719, 9342, 10965 1-4F
    4 7443, 4672, 7772, 9395 1-4F

    2.2 出库口（出库终点）：24 个

    6 个物理位置 × 4 层。

    2.3 充电站：8 个

    站点 ID：7229, 7230, 5244, 5245, 8344, 8345, 9967, 9968

    三、关键参数

    参数 值 说明
    入库货物生成时间 280s 生产口货物生成周期
    出库货物消耗时间 18s 出库口货物消耗周期
    initCargosPercent 50% 初始库位填充比例
    升降梯容量上限 1 升降梯满载阈值（超过则停止跨层派车）
    在线 AGV 30 台 由 上线车辆数(30) 控制
    任务并发上限 50 任务总数或未完成数 < 50 才创建新任务

    四、升降梯负载均衡

    4.1 问题

    GoTo() 是框架黑盒，默认走最短路径，导致所有跨层 AGV 挤同一部升降梯。

    4.2 解决方案

    两段式导航（script.cs 第 11-33 行）：

    1. GetBestElevator(floor)：选负载最小的升降梯
    2. GoTo(门站)：直接导航到该升降梯在目标楼层的门站，强制走指定升降梯
    3. 到达后 callback 中移到附近空闲站台，释放门站

    4.3 辅助方法

    • GetElevatorLoad(mainSta)：统计被某升降梯锁定的 AGV 数量
    • GetBestElevator(floor)：遍历 6 部升降梯，返回负载最小且能到达目标楼层的
    • 升降梯有余量(floor)：负载 < 容量上限时才允许跨层派车

    五、充电逻辑

    5.1 电量仿真（Charge.cs）

    • 每 5 秒消耗 0.0108%（9 小时消耗 70%）
    • 每 10 秒充电 0.069%（2 小时充满）

    5.2 充电触发条件

    AGV 满足全部条件时自动去充电： - 空闲（IsFree()）且空载（IsEmpty()）且可用（IsCanUse()） - 电量 < 40% - 未在充电中 - 状态字段为空

    5.3 充电站选择策略

    1. 优先同层空闲充电站
    2. 升降梯有余量时允许跨层充电
    3. 升降梯满载时只去同层

    5.4 充电中断

    IsWorkingByCharged()：充电中 AGV 若电量 ≥ 60% 可中断充电接任务。

    5.5 并发控制

    Hashtable agvToStaHash + lock(hashLock) 保证多线程下 AGV 到站台的唯一性。

    六、1 楼生产口随机初始化

    1 楼生产口初始 Tag2 = 随机 20~330 秒，使首次生成时间随机分布。之后每轮固定 330 秒周期。

    其他楼层保持原有组偏移 + 层偏移（每层 +6s）错开逻辑。

    代码位置：Method.cs 第 207 行 if (楼层 == 1) 分支。

    七、启动流程（Main 方法）

    阶段1：等待工程加载（Tools.IsOpenedProject）
阶段2：获取 allStas（排除升降梯站、充电站、有货位站）
阶段3：注册 17 个生产口 + 24 个出库口
阶段4：初始化（防推挤、上线 30 台 AGV、随机电量、异步充电定时器）
阶段5：注册 AGV/站台全局属性（状态、上线、类型、车体状况、当前电量）
阶段6：货物初始化（50% 填充库位 + 启动生产/消耗定时器）
阶段7：启动任务创建定时器（模拟 WMS）
阶段8：任务调度主循环（每秒轮询状态机）

    八、统计输出

    PrintStats() 每周期输出： - 充电次数 - 入库/出库完成次数、总耗时、平均耗时、节拍、效率（次/分钟）

    九、依赖

    • ProfControl V8 平台 SDK
    • .NET 6.0（Microsoft.AspNetCore、System.Data.SqlClient 等）
    • MQTTnet（MQTT 通信）
    • Newtonsoft.Json（JSON 序列化）
